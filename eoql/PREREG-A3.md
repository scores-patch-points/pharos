# Amendment A3: superposition is one fold among many, and the schema picks the fold

Written 2026-11-14 AFTER seeing SPEC.md, SPEC-A1.md, SPEC-A2.md and a partial first run; not blind. Stamped with `.sha256` and `.time`. The user said: "super position is just one way of folding things and depends more on things like schema." A related design note by the user (One Log, Many Projections, 2026-11-14, read through the project memory, not re-read here) says a ground is bylined events, conflict rules are asserted events, the default for an unresolved contradiction is "both", and nothing is hardcoded in the kernel because a built-in precedence rule is a ground in disguise. PREREG.md and A1/A2 stand.

## What SPEC.md does today (read)
Collapse is a frame argument F3, a list drawn from a CLOSED vocabulary `all history none drop-retracted latest effective-latest`, defaulting to the ground's declared `collapse` for the kind, else `none` (hold everything). So the default already is "both", and the ground can declare a collapse. Two gaps against the user's point: (1) the vocabulary is fixed in the kernel, and `latest` and `effective-latest` are built-in precedence rules (newest wins), which is the ground in disguise the design note warns about; (2) every fold the spec knows is a way of collapsing a held set of values, so the whole language treats superposition as THE fold and the other folds (accumulate, union, extremum, authority-ranked, per-field merge, sequence merge) as absent.

## Change (declared; EOQL stays small; nothing here is earned)
- **A3-1 A fold is a declaration, not a keyword.** A fold is declared by a schema/ground entry in the log (kind `schema`, byline, position), per kind or per field: its name, its inputs (values, authors, positions, `of` links), its result type, and its identity (what makes two values the same slot). The kernel ships exactly ONE fold, `both` (hold every head; the superposition), plus the identity the log already has. Everything else, including `latest`, `effective-latest`, `drop-retracted`, `history`, `all`, and new ones, is a STARTER SET of declared fold entries woven by a named author in the project's own ground, never built into EOQL.
- **A3-2 The starter set to declare and test** (each a different fold of the same entries): `both` (held set, survivor count), `causal-latest`, `lww-clock`, `first`, `union` (set of values), `sum` and `count` (accumulate), `max` and `min` (extremum), `ranked-by-author` (an authority order declared as events), `per-field` (each field of a body folded by its own declared fold), `append` (ordered list), and `perceiver` (a fold relative to what a given reader could know).
- **A3-3 The schema chooses; the query may only narrow or ask.** The fold used for a slot is the one the governing schema (as of the cut, per A5 of pharos-lazy) declares for that kind or field; a query can ask for the held set instead (always allowed, `both`), can name another DECLARED fold in the ground, but cannot invent one inline. No declared fold for a kind: the answer is `both`, marked `fold: default-both`, never a silent rule.
- **A3-4 Every folded answer cites the declaration that folded it** (the declaring entry's id, author and position), in `explain`, exactly as `cell_basis` cites the writer.
- **A3-5 A change of fold is a REC.** A new schema entry changes what the same entries mean; the log is not rewritten; reading as of a cut before the schema uses the old fold.
- **A3-6 The held count is a property of the `both` fold only.** `_held` and `determined` stay for `both`; other folds report their own result and, where they discard values, how many (`values_discarded`), so the loss is never silent.
- **A3-7 Reframing the power claim (C4).** "Held values with survivor counts" is no longer a headline class. The claim is: EOQL answers questions whose answer depends on which fold the schema declares, by reading that declaration, in one expression, where SQL needs the fold re-implemented in each query. The original beyond-SQL question set and its sealed truth stand and are still scored; the new tests below measure the schema-chooses-the-fold property directly.

## Tests (independent author F; blind to the builder's code; seeds from 20261113)
- **F-A3-1 Same log, different schemas, different correct answers.** One synthetic log (forks, retractions, numeric and text fields, several authors) read under at least 8 different declared folds (the starter set); each answer equals an independent forward fold written by F; the answers differ across folds on at least 80 percent of constructed slots (a fold that gives the same answer everywhere is reported as decorative).
- **F-A3-2 Schema picks the fold.** Weave a schema, read, weave a replacement schema (a REC), read again and read as of the earlier cut: the three answers follow the declared folds; no entry is rewritten (log bytes unchanged apart from appended entries).
- **F-A3-3 Default is both.** With no schema declared, every contested slot returns the held set with `fold: default-both`; no `latest` appears anywhere unless a declaration said so.
- **F-A3-4 Citation.** Every folded answer carries the declaring entry id, author and position; the id exists and its body names the fold; a mismatch between the cited declaration and the fold applied fails.
- **F-A3-5 No inline invention.** A query naming an undeclared fold gets a typed error, never a fallback to a similar built-in.
- **F-A3-6 Per-field fold.** A body whose `status` field folds by `causal-latest`, `count` by `sum` and `tags` by `union` returns the right per-field result in one expression.
- **F-A3-7 Loss is reported.** For every fold that discards values, `values_discarded` equals F's independent count.
Mutants (each MUST be caught): FM1 hardcode `latest` as the default instead of `both`; FM2 accept an inline fold body in a query; FM3 apply the latest schema to a past cut; FM4 omit the citation; FM5 treat a fold with no declaration as `lww-clock`; FM6 mutate the log when the schema changes; FM7 report `_held` for a non-`both` fold as if it were the survivor count of the whole slot.

## What it would teach about EO (stated now)
The wave fold's commitment is that conflict is data and collapse happens at projection. This amendment tests the stronger reading in the design note: if folding rules live in the ground as authored events and the kernel only holds both, then "which fold" is a property of the ground and the same log supports many projections. The outcome that would count against it: if some starter-set fold cannot be expressed as a declared entry without the kernel interpreting a special keyword, the kernel is not small and a ground is hiding in it. The count of such cases is reported.

## Limits
Shows a schema-declared fold registry works on synthetic and the two real logs, and what it costs in expression and evaluation. Does not show the starter set is the right set, that folds beyond it are expressible, or that a reader (human or agent) adopts a ground well; "ground as a bylined event adopted by the reader" is stated but only the declaration and citation are tested here.
