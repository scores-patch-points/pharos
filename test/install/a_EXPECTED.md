# Test author A: expected results, written BEFORE anything was run

Black box. Sources used: PREREG.md, DESIGN.md, door.schema.json, the khora originals, and (for declared touches) each door's `door.json`, which is the public contract. Not read: `install/`, door implementations, the install wiring in `bin/pharos.mjs`.
Files: `a_rig.mjs` (sandbox rig), `a_shimlib.mjs` + `a_shim.mjs` (recording shims), `a_checks.mjs` (the checks, reusable against any CLI), `a_ref/` (trivial reference CLI with planted mutants), `a_rig.validate.test.mjs` (proves the rig and checks detect what they claim), `a_I1.test.mjs` `a_I2.test.mjs` `a_I3.test.mjs` `a_I4.test.mjs` `a_I9.test.mjs` (the real tests, skipped unless `PHAROS_A_RUN=1`).

## Rig facts (what "pass" is measured against)
- Fresh run dir per run under `ledgers/pharos-public/sandbox/a-*/`: `jail/{home,target,tmp,cwd}` (+ `jail/state` when `--state` is used), plus `outside/` (decoy for escape tests), `shims/`, `shimstate/`. `PHAROS_ROOT_ALLOW` = the jail. HOME and TMPDIR point into the jail. Environment is built from scratch (nothing inherited).
- On macOS every run is wrapped in `sandbox-exec`: writes outside the run dir are denied, network is denied except loopback ports the rig itself listens on (an ephemeral dead port used as every proxy variable and `OLLAMA_HOST`, plus 11434, 11436, 11438, 4096 when free). A denied write shows up as EPERM in output and is reported as a violation.
- Shims (record every call as JSON line, fail closed, exit 97, never run the real tool): brew curl wget launchctl ollama npm opencode sudo docker git claude open lsof. Read-class calls (`--version`, `list`, `ls`, `getenv`, git `rev-parse`/`status`/`log`, lsof) answer with canned output and are logged as `read`; everything else is `mutating` and blocked. Exception: `launchctl setenv/unsetenv/getenv` is emulated against `shimstate/launchctl.json` so env restore can be checked. `node` is the real node via a symlink. Anything not shimmed (`/usr/bin/*`) is real, so absolute-path calls are only caught by the tree hashes and the sandbox profile.
- Tree hash = lstat walk, never following links: type, permission bits (incl. setuid bits and directory modes), symlink target text, size, sha256 of content. No mtimes.
- "Declared" = the door's `door.json` with tokens expanded: files and configs paths (globs `*` `**`; a directory counts if it is an ancestor of a declared path), env names, tools. Read-class probe calls are allowed for tools in `requires.tools` or `touches.tools`; mutating calls only for `touches.tools`. `$STATE` is NOT implicitly declared: journal paths must be covered by `touches.files`.
- Undo is run without `--apply` (DESIGN section 3 shows no flag for it). If the installer says undo needs `--apply`, the test fails with that message rather than adapting.

## Expected results of the rig validation (reference CLI, not the installer)
- Clean reference: every check returns zero violations (I1, I2, I3a, I3b, I4).
- Each planted mutant is caught by at least the check named next to it. 13 mutants, M1..M7 are PREREG's, the rest are extra rig-sensitivity probes:
  M1 dry-write (I1 tree hash), mode (I1 mode-only change), state-leak-dry (I1 empty dir), dry-shim (I1 shim call), net (I1 listener), M2 undo-skip (I3), M3 undeclared (I2), M4 double-append (I3 idempotent apply), M5 symlink-ok (I4), M6 undeclared-shim (I2), M7 ignore-flag (I4 gating, plus I2 where the flag is absent), dotdot-ok (I4), unknown-ok (I4), outside-write (sandbox EPERM, I2).
- The guard test: a script that tries to write outside the run dir and to connect to a non-listener port gets EPERM for both; connection to the dead listener is counted.
- If any of the above fails, the rig is wrong and no result from it may be used.

## Expected results against the real installer (predictions, so the miss is visible)
Confidence in brackets. These are predictions, not requirements; the requirements are PREREG.
- I1 dry run is pure: PASS for `install <door>`, `--plan`, `--json`, `detect`, `verify`, `status` on every door, and with all heavy flags given but no `--apply` [75%]. Most likely failure: the runner creates `$STATE` (an empty directory or journal) during plan, or a detect-only door exits non-zero on plan. Zero connections and zero mutating shim calls [90%].
- I2 touched within declared: PASS for pharos-core and agents-md default apply [55%]. Most likely failure: the journal under `$STATE` is written but `touches.files` does not list `$STATE/**` (a manifest gap, reported as its own line), or a detect probe tool is not listed under `requires.tools`/`touches.tools`. reader-stack with `--with-opencode --opencode-config` and `--with-launchctl`: PASS if env names are declared and the launchctl calls are the only tool calls [60%].
- I3a apply then undo restores HOME and TARGET byte for byte with the journal in an external `--state`: PASS for pharos-core, agents-md and reader-stack (opencode config, launchctl) [70%]. Most likely failure: an existing AGENTS.md without a trailing newline or with CRLF comes back different, or a created directory is left behind.
- I3b same with the default in-target state: the whole jail including `.pharos/` must be identical. I predict FAIL [60%] because an append-only journal is expected to survive undo; if it fails, the difference must be confined to the state dir (the report says so). This is flagged as an ambiguity in PREREG ("sandbox tree"), not softened: it is reported as failed if the tree differs.
- Apply twice changes nothing the second time (HOME and TARGET): PASS [75%]; exit code of the second apply is reported, not asserted. Undo twice: PASS [75%]; same note.
- All doors in sequence (apply each in order, undo in reverse; and `install all` then `undo-door all`): PASS [60%].
- I4 flag gating: reader-stack `--apply` alone makes zero mutating shim calls, edits no config, mentions all four flags in its output, changes nothing outside declared [70%]. Each of `--with-ollama`, `--with-launchctl`, `--with-opencode`, `--with-services` alone causes no call belonging to another flag's tools [65%]; `--with-ollama` alone is expected to exit non-zero because the brew shim fails closed.
- I4 refusals: unknown door, `..` targets, symlinked target: non-zero exit and nothing changed anywhere [75%]. Exit code 3 for refusals is noted but only non-zero is required. Weak spots: an unknown door name falls through to the legacy `install <repoDir>` and might create a directory [30% chance it does]; an in-target symlink `AGENTS.md` pointing outside (DESIGN 1.5 "realpath on every write", beyond PREREG's wording) [40% chance it is written through].
- I9: the frozen pre-change copy (taken 2026-11-12 before the installer existed; hashes in `sandbox/baseline/pharos-pre.sha256`) runs 32 tests with 31 passing and 1 failing ("pharos itself is ignorant of its siblings", because `kinds.json` names sibling repos). Expected for the new tree: the 31 passing names still pass [80%]; the 1 baseline failure still fails and probably gets more hits because new files will name khora and other repos [70%]. This is reported as "pre-existing failure", not as a regression and not as a pass. Legacy commands (`init weave fold status merge install <dir> undo <dir>`, usage, errors): identical exit code, stdout, stderr and resulting tree against the frozen copy, volatile lines (timestamps) masked [85%]. The documented edge (a bare relative directory literally named like a door) is reported as informational and is expected to differ.
