# Amendment A2: the model adapter's output constraints are constants of the protocol

Written 2026-11-13 BEFORE any real-model result or real question existed. Stamped with `.sha256` and `.time`. `PREREG.md` and A1 stand; this adds to section 7 (models) and section 8 (constants across arms).

What was found (first contact with a real local model, qwen3:4b via Ollama, three STUB questions; no claim about the pharos): with Ollama's default the model puts its whole output budget in a hidden thinking field and the reply is empty; with `think: false`, and with the `/no_think` switch, it still wrote about 300 tokens of plain-text reasoning and never reached the JSON object (every question ended as a format failure, about 170 seconds each while another model was downloading); with Ollama's constrained JSON output (`format: "json"`) and `think: false` it answered in 19 tokens and about 5 seconds.

Fixed now, for EVERY model, EVERY arm and the closed-book and full-context arms alike, recorded in each adapter's `info().params`: temperature 0; `think: false`; constrained JSON output (`format: "json"`, or the runtime's equivalent); seed as in section 6. These are constants not under test. Consequences stated so they are not mistaken for results: (1) a model that cannot be given constrained JSON output by its runtime is run with the same prompt and the format-failure count is reported (M8); (2) constrained decoding removes one failure source (format) and leaves content errors, so M8 will understate how hard the protocol is for an unconstrained model; (3) thinking is off, so the result is about answering from pointers and excerpts, not about deliberation; a thinking-on arm may be added later as a labelled extra, never pooled.
